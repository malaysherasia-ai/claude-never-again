# L001: no heredoc inside $(...)

**Filed:** 2026-09-21, while releasing 1.6.0. Form: hook, warn mode.

**Symptom.** The new capture check passed 250 checks on Windows and the
Ubuntu CI job, and every one of its checks failed on macOS with
`_capture.sh: line 107: syntax error: unexpected end of file`.

**Cause.** macOS ships bash 3.2. Its parser reads the body of a `$(...)`
substitution by scanning for the closing paren while honouring quotes. A
heredoc inside it whose body holds an apostrophe, which any real Python
does, makes the scan run to the end of the file. The script had two such
blocks: the message extractor and the fix test.

**Rule.** No heredoc inside `$(...)`. Run the command with its heredoc as a
plain statement, send its output to a file or a variable, and read that.
For this tool, put the Python in `na` as an internal command and call it.

**Fix.** The two Python blocks moved into `scripts/na` as
`_commit-message` and `_looks-like-fix`; `_capture.sh` calls them. The
hook template's example, which recommended the broken shape, now shows
the file-then-read form.

**What would have gone red:** the macOS CI job, and it did. But only for
code a test exercises, and only after a push. The hook looks at every
shell file in the commit, before the push, for one grep's worth of time.
