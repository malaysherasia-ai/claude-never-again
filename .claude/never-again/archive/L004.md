# L004: a commit hook also runs for merges, amends and `-v`

**Filed:** 2026-09-22, from the review of the 1.6.0 branch. Form: rule line.

**Symptom.** The capture check, reviewed before merge, asked about a
merge of a `fix/*` branch, asked a second time when a fix commit was
amended, and read the diff that `git commit -v` puts below the scissors
line as if it were the message. In block mode each of those refused a
commit that had already answered.

**Cause.** The check was written for the plain case, one new commit with
a `-m` message, and tested for that. git runs the same commit-msg hook
for a merge, an amend and a verbose commit, and each hands it something
that is not a new message from the person.

**Rule.** Before a commit-time check ships, walk it through the other
ways a commit happens: merge, amend, `-v`, an editor with no `-m`, a
custom `core.commentChar`, the first commit of a repo. Decide what each
one means for the check and write that down as a test.

**Fix.** Merges are skipped (MERGE_HEAD on the git side, the merge
message shape on both), an amend is skipped (`--amend` in the command;
under git, a message identical to HEAD's), the message file is cut at
the scissors line and read with the repo's comment character, and an
unborn branch is "initial" on both sides of the `na none` mark.

**What would have gone red:** nothing. A judgement rule: a script cannot
list the cases a check has not thought about.
