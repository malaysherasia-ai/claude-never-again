# L002: `grep -c` exits 1 on zero matches

**Filed:** 2026-09-21, while releasing 1.6.0. Form: rule line.

**Symptom.** A test that asserted "dry run wrote nothing" failed with
`[: 0\n0: integer expected`. The log was empty, which is what the test
wanted.

**Cause.** The helper was `[ -f "$LOG" ] && grep -c . "$LOG" || echo 0`.
`grep -c` prints `0` for an empty file and then exits 1, because it found
nothing. The `|| echo 0` ran as well, and the helper printed two zeros.
Every earlier caller had a non-empty log, so it never showed.

**Rule.** `grep -c` reports the count in its output and "found anything"
in its exit code; the two disagree at zero. Never chain `|| echo 0` after
it. Use `if`/`else` on the file's existence and `|| true` on the grep.

**Fix.** `logn()` in `tests/hooks.sh` became
`if [ -f "$LOG" ]; then grep -c . "$LOG" || true; else echo 0; fi`.

**What would have gone red:** nothing before this test. A judgement rule:
a script cannot tell a `||` that is wrong from one that is meant.
