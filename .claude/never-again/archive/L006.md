# L006: a notice an agent must act on is a stopped command

**Filed:** 2026-09-23, from the seventh field run (an Antigravity session
on a repo one release behind). Form: rule line.

**Symptom.** The session worked through a whole task on a stale release
and never said the repo needed `na upgrade`, though the daily check had
found the newer release. Asked afterwards, the agent proposed a rule in
`AGENTS.md` telling it to read the stderr of background terminals.

**Cause.** The release nudge was delivered as two reminders. On the IDE
path it is a `systemMessage` in a hook answer the IDE never asks for. On
the git path it is one line on the stderr of a `git commit` that exited
0, in a terminal the agent does not read once the command succeeded. The
agent's proposal was a third reminder, and the same `AGENTS.md` already
carries the block that tells it to file lessons, which it does only when
prompted. The tool that exists to replace reminders with enforcement was
using a reminder for its own upkeep.

**Rule.** A notice the agent must act on stops the command. A line printed
by a command that succeeded is a reminder, and gets skipped. When a hook
has something the agent has to do, refuse the command and put the way out
in the reason.

**Fix.** `"updates": "block"` in `state.json`: a stale release refuses the
next commit, from every agent's hook and from git's pre-commit, with
`na upgrade` as the way out and `na upgrade --later` to defer for a day or
until the next release. Repos that register Antigravity get `"block"` when
the agent joins, since only the git side reaches that IDE. A stopped commit
is a fired call in `calls.log`; the nudge never was.

**What would have gone red:** nothing. The tests for the nudge checked that
the line was printed, never that anything read it.
