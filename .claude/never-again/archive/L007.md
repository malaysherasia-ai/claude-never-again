# L007: a subprocess read as text names its encoding

**Filed:** 2026-09-24, while building 1.9.0. Form: hook (warn).

**Symptom.** The first `na review` run on the tool's own repo crashed:
`UnicodeDecodeError: 'charmap' codec can't decode byte 0x81` inside
subprocess's reader thread, then `AttributeError: 'NoneType' object has no
attribute 'strip'` in `_git`, because the failed read left stdout as None.
`na stale --commits 5` on the same repo printed "nothing stale", which was
wrong for the same reason: the git text came back empty.

**Cause.** `subprocess.run(..., text=True)` decodes the child's output with
the locale's code page, cp1252 on Windows. Git prints commit messages and
paths as UTF-8, and this repo's messages carry em dashes. The installer had
the same bug on CLAUDE.md in 0.1.0 (fixed there with explicit UTF-8), so the
rule existed in one file and not in the CLI. Three call sites in `na` were
affected; the manifest script already decoded bytes by hand.

**Rule.** A subprocess read as text passes `encoding="utf-8",
errors="replace"` on the same line as `text=True`. Windows decodes with
cp1252 otherwise, and any non-ASCII byte in git's output crashes the read.

**Fix.** All three `subprocess.run` calls in `na` pass the encoding. The
hook checks every changed Python file, `scripts/na` and the templates for a
`text=True` or `universal_newlines=True` with no `encoding=` on the same
line. Sweep at filing: clean.

**What would have gone red:** nothing. CI runs the suites on Windows, but
the test repos' commit messages are ASCII.
