# L008: "since the last commit" is a question about HEAD, not the clock

**Filed:** 2026-09-24, from the first CI run of the failure record (PR
#33). Form: rule line.

**Symptom.** Two checks in the new "the failed call is the witness"
section failed on the Ubuntu runner and passed on macOS and Windows: `na
failures` listed nothing after a failure had been written, and a retry of
the same command was not matched as flaky.

**Cause.** The window "since the last commit" was drawn by timestamp: a
line counted when its second was later than the last commit's `%ct`. On
the fast runner the failure was written in the same second as the commit
before it, and `>` put it on the wrong side. The slower runners happened
to cross a second boundary. Seconds cannot order two events that share a
second, and `>=` would only have moved the same ambiguity to the other
end of the window (a pass written in the same second as the commit that
landed it would stay in the next window).

**Rule.** A window that means "since the last commit" is anchored to the
commit, not to the clock: record the HEAD each line was written under and
select the lines written under HEAD as it is now. Timestamps are for
display and ageing, never for ordering against a commit.

**Fix.** `failures.log` carries a `head` column; `open_failures` and
`fixed_failures` read the lines whose head is the current HEAD. Under the
agent's PreToolUse hook and git's commit-msg hook HEAD is still the old
commit, so the lines match and the commit is asked; once it lands HEAD
moves and the record is behind it, whatever the clock says. The same idea
already held for `na none` (it records HEAD, not a time).

**What would have gone red:** the suite did, on one of three runners. The
local run passed because a Windows machine is slow enough to cross a
second between the commit and the first hook call.
